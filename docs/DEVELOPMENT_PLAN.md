# Focuselle — план разработки приложения для macOS

Стек и название Focuselle утверждены 18 ноября 2026 года. Ранее приложение использовало рабочее название Fowcus. Доступность доменов и товарного знака Focuselle предстоит проверить.

## Продукт и дизайн

Приложение для macOS объединяет помодоро, задачи с подзадачами, план дня с временными блоками, статистику и фоновые звуки. Работа доступна без аккаунта с локальным хранением. Первый выпуск поддерживает русский и английский языки.

Визуальная основа — монохромная палитра Lumyboo, круглый таймер, постоянная полоса навигационных иконок с подсказками, скрываемый план дня, компактные скруглённые элементы управления. Тема выбирается в настройках. Настраиваемые пресеты можно закреплять над таймером.

Зафиксированная версия дизайна находится в design/snapshots/2026-11-18. Рабочие Fowcus.html, workspace.css и pickers.js содержат последние интерактивные изменения. При переносе сверяться с ними. Веб-файлы служат ориентиром для нативного интерфейса.

Windows исключена из текущего объёма.

## Утверждённый стек

- Swift — модель данных, таймер, хранение и системные интеграции.
- SwiftUI — основной интерфейс и настройки.
- AppKit — управление окнами, строка меню, плавающий мини-таймер и точечные интеграции.
- SQLite — задачи, сессии, временные блоки и миграции схемы.
- UserDefaults — тема, язык, закреплённые пресеты и настройки окон.
- AVFoundation — локальные фоновые записи и сигналы завершения.
- UserNotifications — уведомления с разрешения пользователя.
- Xcode и XCTest — сборка и проверки критической логики.
- Developer ID, подпись и notarization — распространение через DMG.

Предлагаемая стартовая совместимость — macOS 14 и новее. Проверить её перед созданием проекта на целевых Mac и доступном SDK. Новые системные API подключать через проверки доступности.

## 1. Нативный каркас и проверка системных возможностей

Создать Xcode-проект. Разделить код на представления, прикладную логику и хранение. Подключить русский и английский через String Catalog.

Собрать основное окно, настоящие системные кнопки окна, полосу навигации, скрываемый план дня и настройки темы. Проверить прототип строки меню и отдельного плавающего NSPanel.

Готово, когда приложение запускается как .app, обе темы работают, навигация доступна с клавиатуры, мини-окно и строка меню используют общий источник состояния. Согласовать минимальную версию macOS.

## 2. Данные и восстановление состояния

Создать SQLite-схему и последовательные миграции:
- Task — идентификатор, название, плановая дата, оценка в помодоро, статус, время завершения, порядок.
- Subtask — родительская задача, название, статус, порядок.
- FocusSession — идентификатор, необязательная задача, снимок названия, начало, конец, фактическое время фокуса, статус.
- TimeBlock — задача, дата и границы интервала.
- TimerPreset — фокус, короткий и длинный отдых, частота длинного отдыха, закрепление.
- ActiveSession — состояние текущего интервала для восстановления после перезапуска.

Сохранять изменения транзакционно. Хранить моменты времени однозначно, отдельно учитывать плановую локальную дату задачи и дату сессии для статистики. Определить поведение при смене часового пояса.

Готово, когда задачи и история переживают перезапуск, миграции сохраняют существующие данные, повторная обработка завершения сессии не создаёт дубликатов.

## 3. Таймер и системные окна

Реализовать состояния готовности, фокуса, паузы, отдыха и завершения. Поддержать 25/5, 50/10, 90/10, свои интервалы, закрепление и удаление пользовательских пресетов.

При первом запуске предложить выбрать ритм и закрепить его. Таймер запускается с задачей или без неё. Переназначение во время фокуса должно явно завершать или разделять учёт времени.

Обеспечить работу при закрытом основном окне, сон/пробуждение и восстановление после сбоя. Обновление цифр не должно быть источником истины для длительности. Определить политику сна: время сна не записывать как активную работу без явного решения пользователя.

Основное окно, строка меню и мини-таймер синхронно запускают и приостанавливают один интервал. После завершения предложить отдых. Автостарт настраивается пользователем.

Готово, когда сессия учитывается ровно один раз и корректно восстанавливается после паузы, сна и перезапуска. Проверить эти сценарии автоматизированно и на реальном Mac.

## 4. Задачи и календарь

Реализовать добавление, редактирование, завершение, подзадачи, оценку, перенос даты и упорядочивание. Добавить явное управление удалением и отмену удаления. История сессий сохраняет название удалённой задачи.

Сделать календарь выбранного дня и недельное расписание для тайм-блокинга. Поддержать создание и редактирование блоков, проверку пересечений и переход из блока к фокусу по задаче.

Готово, когда пользователь планирует задачу, выделяет ей время, запускает фокус и видит результат в истории. Проверить пустые дни, длинные названия и переходы между месяцами.

## 5. Статистика

Показывать за выбранный день задачи, выполненные и оставшиеся, долю выполнения, число помодоро и время по каждой задаче. Сессии без задачи показывать отдельной строкой. Добавить недельный обзор и просмотр сессий задачи.

Отдельно определить учёт незавершённых сессий, позднего завершения задач и сессий через полночь. Отображать фактические минуты фокуса отдельно от числа полностью завершённых помодоро.

Готово, когда цифры воспроизводимо совпадают с сохранёнными сессиями и статусами задач. Проверить исторические даты, удалённые задачи, переход суток и смену часового пояса.

## 6. Звуки и рабочий ритуал

Подключить лицензированные локальные записи дождя и кафе, белый шум, громкость и плавное включение/выключение. Указать происхождение и условия использования записей в ресурсах проекта.

Добавить настройки звука окончания, автоматического отдыха и короткий сценарий подготовки к фокусу.

Готово, когда звуки работают офлайн, не щёлкают на стыках и корректно реагируют на отключение аудиоустройства. Проверить с наушниками и при смене устройства вывода.

## 7. Защита фокуса

Сначала выполнить отдельную техническую проверку блокировки сайтов и приложений на обычном пользовательском Mac. Проверить доступные публичные API, разрешения, подпись, установку и безопасное снятие ограничений.

Реализовать мягкий режим и выход с задержкой. Для строгого режима отдельно утвердить достижимые ограничения и восстановление после сбоя. Полную невозможность обхода владельцем Mac считать неподтверждённым требованием до исследования.

Готово, когда правила применяются только на время выбранной сессии и снимаются при её штатном завершении. Проверить аварийное закрытие, перезагрузку и отказ в разрешении. Решение о включении строгого режима в первый публичный выпуск принять по результатам проверки.

## 8. Подготовка первого выпуска

Использовать утверждённое название Focuselle в приложении и установщике. Проверить доступность доменов и товарного знака и выбрать bundle identifier до выпуска. Создать иконку приложения.

Провести визуальную проверку всех экранов в обеих темах, русский/английский, VoiceOver, клавиатурную навигацию, увеличение текста и Reduce Motion. Сравнить с сохранённым дизайном и устранить переполнения.

Собрать Release для согласованных архитектур Mac, подписать, пройти notarization, приложить ticket и создать DMG. Проверить установку на чистом Mac, перенос в Applications, первый запуск, обновление поверх предыдущей версии и сохранность базы.

Готово, когда есть устанавливаемый подписанный DMG и пройден основной пользовательский сценарий на целевых Mac. Для подписи нужен доступ к Apple Developer и сертификату владельца приложения.

## Последующая серверная часть

Админ-панель остаётся требованием, но требует отдельного согласования аккаунтов и состава собираемых данных. Локальная база задач сама по себе не даёт администратору список пользователей.

После согласования спроектировать сервер, аутентификацию, права администратора и минимально необходимый учёт установок/аккаунтов. Go и PostgreSQL остаются предложением для этого этапа, отдельного утверждения серверного стека ещё не было.

Синхронизация, подписка и платный строгий режим — последующие этапы. До разработки подписки определить продуктовые ограничения и способ оплаты.

## Порядок исполнения

Выполнять этапы последовательно с проверяемым результатом каждого. Техническое исследование защиты фокуса из этапа 7 провести сразу после каркаса, чтобы его ограничения стали известны до основной реализации.

### Состояние на 18 ноября 2026

Разработка начата по команде пользователя. В качестве предварительного deployment target выбрана macOS 14; реальная проверка на этой версии и окончательное согласование совместимости остаются открытыми.

Создан `Focuselle.xcodeproj`, SwiftUI-каркас с системной рамкой окна, навигацией, скрываемым планом, темами и русским/английским String Catalog. Основное окно, MenuBarExtra и плавающий NSPanel подключены к одному AppState. Настройки темы, языка и видимости плана сохраняются в UserDefaults.

Добавлен минимальный таймер для проверки общего состояния: старт, пауза, продолжение, сброс, три ритма и три режима. Время измеряется монотонными часами, сон ставит таймер на паузу. Сохранения сессий и восстановления после перезапуска пока нет. Остальные разделы честно обозначают предстоящие функции.

На текущем Mac установлены только Command Line Tools, поэтому добавлен `scripts/build.sh`, который собирает настоящий `.build/Focuselle.app` с локальной подписью без полного Xcode. Сборка и отдельные проверки критической логики таймера прошли. Формат Xcode-проекта проверен `plutil`, но сборка через Xcode ещё не выполнена. Визуальная проверка окон, клавиатуры и тем не завершена: инструмент Computer Use сообщил об отсутствии разрешения. Этап 1 пока не считается полностью принятым.

Приложение также успешно запущено через Launch Services вне песочницы, работающий процесс подтверждён. Подпись проверена `codesign --verify`. Это не заменяет визуальную проверку.

Следующий шаг — ручная проверка каркаса по README, устранение найденных проблем, затем техническое исследование защиты фокуса до основной реализации данных. Каталог строк включён в ресурсы Xcode-проекта; CLI-скрипт генерирует из него `.strings`, не создавая второго источника переводов.
