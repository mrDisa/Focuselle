# Защита фокуса на macOS: техническая проверка

Дата: 18 ноября 2026. Целевая платформа Focuselle: нативная macOS 14+, распространение вне Mac App Store через Developer ID и DMG.

## Результат

Для первого прототипа подходит мягкий режим: реагировать на активацию выбранного приложения и предлагать вернуться к фокусу. AppKit позволяет попытаться скрыть приложение, но это не запрет запуска: пользователь может вернуть его обратно. Реальную блокировку сайтов и запрет исполнения приложений нужно проверять отдельными подписанными прототипами. Обещать «невозможно обойти до конца таймера» на личном Mac пока нельзя.

Это исследование API и требований к поставке, а не готовая защита. Никакие ограничения на этом Mac не устанавливались. Проверка установленного фильтра, аварийного закрытия и перезагрузки ещё не выполнена.

## Варианты

| Вариант | Возможности | Установка и разрешения | Решение для Focuselle |
| --- | --- | --- | --- |
| AppKit: NSWorkspace + NSRunningApplication | События активации, попытка скрытия приложения | Обычное приложение; реальные результаты скрытия нужно проверить | Первый мягкий прототип; не называть системной блокировкой |
| FamilyControls + ManagedSettings | Screen Time control API | AuthorizationCenter и ManagedSettingsStore недоступны нативной macOS в текущем SDK | Не использовать в нативном target |
| Safari Content Blocker | Декларативная фильтрация в Safari | Отдельное расширение и включение пользователем | Возможный браузерный вариант, не общесистемная защита |
| NetworkExtension Content Filter | Разрешение/отклонение сетевых потоков | System extension, provisioning с Network Extension entitlement, Developer ID для прямой поставки, одобрение системы | Кандидат для отдельного исследования системной фильтрации |
| EndpointSecurity | Авторизация событий исполнения процессов | Entitlement по запросу Apple, Full Disk Access; отдельная системная интеграция | Не включать в первый мягкий режим |

AppKit предоставляет уведомления через `NSWorkspace.shared.notificationCenter`; `NSRunningApplication.hide()` возвращает признак успеха и может не скрыть приложение. Это позволяет предложить мягкий возврат к работе, но не предотвращает переключение или перезапуск. Источники: [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace), [hide()](https://developer.apple.com/documentation/appkit/nsrunningapplication/hide()).

Наличие модуля FamilyControls не означает наличие Screen Time управления на macOS. У `AuthorizationCenter` в документации указаны iOS/iPadOS, а установленный Swift interface явно помечает класс `@available(macOS, unavailable)`. Аналогичная пометка есть у `ManagedSettingsStore`. Проверено отрицательной компиляцией, не только `canImport`. Источник: [AuthorizationCenter](https://developer.apple.com/documentation/familycontrols/authorizationcenter).

У Content Filter на macOS в таблице Apple указан system extension с macOS 10.15, без требования supervised device. Ограничение supervised из iOS нельзя автоматически переносить на Mac. Для прямой поставки требуется соответствующее разрешение Network Extension в профиле Developer ID. Новый URL Filter в той же таблице начинается с macOS 26 и не покрывает нашу минимальную macOS 14. Источники: [TN3134](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment), [Network Extensions Entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension).

Системный фильтр не гарантирует распознавание полного HTTPS URL во всех браузерах. `NEFilterFlow.url` заполняется для потоков из WebKit browser objects; для остальных потоков нельзя рассчитывать на это поле. Следовательно, до рабочего прототипа не обещаем одинаковую доменную или URL-фильтрацию Safari/Chrome/Firefox, работу с VPN, DoH, QUIC и уже открытыми соединениями. Источник: [NEFilterFlow.url](https://developer.apple.com/documentation/networkextension/nefilterflow/url).

Safari Content Blocker получает правила от содержащего приложения и работает внутри Safari. При изменениях приложение вызывает перезагрузку правил. Архитектурный вывод: нельзя считать закрытие Focuselle автоматическим снятием таких правил — отдельный механизм срока действия ещё нужно исследовать. Источники: [Creating a content blocker](https://developer.apple.com/documentation/safariservices/creating-a-content-blocker), [reloadContentBlocker](https://developer.apple.com/documentation/safariservices/sfcontentblockermanager/reloadcontentblocker(withidentifier:completionhandler:)).

EndpointSecurity даёт события исполнения процессов, но создание клиента требует entitlement Apple и Full Disk Access. Даже наличие `AUTH_EXEC` не доказывает готовую защиту приложения целиком: процессы-помощники, уже запущенные приложения и обход владельцем требуют самостоятельной проверки. Источники: [Endpoint Security](https://developer.apple.com/documentation/endpointsecurity), [entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client), [es_new_client](https://developer.apple.com/documentation/endpointsecurity/es_new_client(_:_:)).

## Что проверено на текущем Mac

Команда: `./scripts/probe-focus-protection.sh`.

- Установленный SDK: macOS 27.2; typecheck выполнен для `arm64-apple-macosx14.0`.
- Декларации AppKit, NetworkExtension, SystemExtensions, SafariServices и EndpointSecurity успешно компилируются.
- Обращение к `AuthorizationCenter.shared` и создание `ManagedSettingsStore` ожидаемо отвергнуты компилятором именно из-за недоступности в macOS.
- Скрипт сохраняет диагностику в `.build/protection-probe/`, не добавляя артефакты в Git.
- Код проб только проверяется компилятором. Он не скрывает приложения, не читает историю браузера, не вызывает установку расширений и не запрашивает разрешения.

Локальная сборка Focuselle использует ad hoc подпись. Это достаточно для проверенного запуска обычного приложения на данном Mac, но не доказывает возможность установки system extension. По процедуре Apple система проверяет расположение содержащего приложения в Applications, подписи, entitlement команды разработки и идентификаторы расширения. Источник: [Installing System Extensions and Drivers](https://developer.apple.com/documentation/systemextensions/installing-system-extensions-and-drivers).

## Предлагаемое поведение мягкого режима

Это предложение для реализации, не уже включённая функция и не утверждённое ограничение первого выпуска.

1. Пользователь явно выбирает приложения и включает защиту на время фокуса.
2. Наблюдение действует только при активном фокусе, не во время отдыха или паузы. Уведомления после завершения/сброса игнорируются по идентификатору сессии.
3. При активации выбранного приложения показывается предложение вернуться. Скрытие допустимо как отдельно выбранное поведение; принудительно завершать процессы не требуется.
4. Для выхода — короткая отсрочка с возможностью отмены. Она не препятствует аварийному завершению Focuselle владельцем Mac.
5. После штатного выхода, сброса или завершения сессии наблюдатель снимается. После сбоя процесса наблюдение отсутствует; пользователь может открыть ранее скрытое приложение обычным способом.
6. Finder, System Settings, Terminal и само приложение не включаются в первоначальный набор ограничений. Расширение списка потребует проверки восстановления доступа.

## Условия будущего системного прототипа

Перед реализацией фильтра выбрать окончательный bundle identifier и получить доступ к подписи Developer ID и профилю Network Extension. Установка на обычный Mac должна проходить с включёнными штатными защитами системы; обход проверок подписи не является проверкой поставляемого продукта.

Предлагаемая модель снятия ограничений: расширение получает ограниченную по времени «аренду» правил, идентификатор сессии и heartbeat. Истечение срока или потеря связи снимает ограничения внутри расширения независимо от UI. Это проектное требование, которое ещё нужно реализовать и проверить. Оно даёт приоритет восстановлению доступа и допускает обход завершением приложения; строгий режим нельзя автоматически строить на противоположном поведении без отдельного продуктового решения.

Проверки для подписанного прототипа:

| Сценарий | Критерий |
| --- | --- |
| Отказ в установке/разрешении | Фокус работает; UI не сообщает о включённой защите |
| Включение и штатный конец | Контрольный сайт/приложение ограничен только внутри сессии; снятие подтверждено фактическим открытием |
| Выход с задержкой и отмена выхода | Однозначное состояние во всех трёх поверхностях, без преждевременного снятия |
| Сброс/отдых/пауза | Соблюдается выбранная политика, нет оставшихся правил |
| Авария UI или расширения | Доступ восстанавливается по проверенному механизму; нет бессрочных правил |
| Сон, пробуждение, перезагрузка | Старые правила не возобновляются без действующей сессии |
| VPN/DoH/QUIC, смена сети, разные браузеры | Задокументирован фактический охват; нет обещания универсальной фильтрации |
| Обновление и удаление | Данные сохранены, расширение корректно деактивируется |

Пока эти сценарии не пройдены, строгая системная блокировка остаётся экспериментом. Исследование API достаточно для выбора мягкого прототипа; оно не закрывает критерии приёмки этапа 7. Основную работу над локальными данными можно продолжать без зависимости от неподтверждённой строгой защиты.
